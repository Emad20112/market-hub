# ADR-006 — خطة الاختبارات

**الحالة:** معتمد | **التاريخ:** 2026-11-07

## مستويات
1. **وحدات Domain (نقية):** كل قاعدة عمل تُختبر بلا قاعدة بيانات — `vitest`،
   سريعة (ms). إلزامية لكل Use Case: قاعدة واحدة = اختبار واحد على الأقل.
2. **تكامل Use Case على قاعدة محلية:** سكربت `supabase start` + معاملة تُرجَع
   `ROLLBACK` بعد كل اختبار (helper في `src/server/shared/testing/`) —
   قاعدة نظيفة دائمًا، بسرعة عالية.
3. **اختبار معاملة مالية:** لكل عملية مالية: مسار ناجح + فشل جزئي يثبت الـ rollback
   الكامل + تزامن (عمليتان متوازيتان، أرصدة صحيحة).
4. **اختبارات تكافؤ (Equivalence):** عند نقل كل RPC: تشغيل القديمة والجديدة على
   نفس بيانات الاختبار ومقارنة المخرجات رقمًا رقمًا (المبالغ، الأرصدة، الأرقام
   المسلسلة، رسائل الخطأ) — بوابة قبل حذف الدالة.
5. **اختبارات قبول SQL قائمة:** `supabase/tests/*.sql` تظل تعمل بعد كل مرحلة
   (تُحدَّث عند إسقاط دالة).

## التشغيل
- `npm run test:server:unit` (vitest) | `test:server:int` (قاعدة محلية).
- CI محلي: قبل إغلاق كل مرحلة (§ خطة الانتقال).

## القواعد
- لا حذف دالة SQL بلا اختبار تكافؤ سابق لمُعاد تنفيذها.
- كل Use Case مالي له اختبار معاملة — لا استثناءات.

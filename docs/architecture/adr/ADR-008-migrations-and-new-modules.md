# ADR-008 — قواعد Migrations وخطط إضافة الوحدات

**الحالة:** معتمد | **التاريخ:** 2026-11-07

## قاعدة Migrations (مثبتة)
ملفات `supabase/migrations/` مسؤولة فقط عن: الجداول، العلاقات (FK)، الفهارس،
القيود، الأنواع/Enums، RLS، والمشغلات الضرورية لحماية البيانات.
**لا تحمل منطق أعمال — لا استثناء.** أي منطق جديد يذهب إلى `src/server/`.
القواعد التفصيلية الحالية في `supabase/MIGRATIONS_RULES.md` تبقى سارية ويُضاف
إليها هذا البند.

## إضافة وحدة/نطاق جديد (Checklist)
1. تحديد موقع النطاق في التسلسل الطبقي (ADR-007) — الاعتماد للأعلى فقط.
2. `src/server/domains/<name>/` بالهيكل القياسي + `MANIFEST.md` (owner، حدود،
   جداول مملوكة، عقود).
3. أنواع/عقود قبل أي دالة: `contracts/` + `validators/`.
4. Domain نقية + اختباراتها، ثم Repositories، ثم Use Cases مع `authorize`.
5. Server functions + ربط الواجهة عبر `index.ts` فقط.
6. اختبار معاملة لأي عملية مالية + اختبار تكافؤ إن كان يستبدل RPC.
7. تحديث خريطة الاعتماديات (`arch-dep-scan`) ووثائق النطاق.

## سجل القرارات والتوثيق
- كل حذف/نقل/تغيير سلوكي يوثق في `docs/architecture/adr/DECISIONS-LOG.md`
  (الدالة، القرار، السبب، أدلة المستدعين، نتائج اختبار التكافؤ، التاريخ).
- لا تغيير سلوكي صامت أثناء النقل — أي انحراف مكتشف يُبلَّغ ويُعتمد قبل تنفيذه.

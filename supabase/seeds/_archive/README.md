# _archive — ملفات موروثة

هذا المجلد يحتوي ملفين موروثين **لا يعملان**، محفوظين للمرجعية فقط.

## لماذا هما هنا لا في `03_samples/`؟

لأن كليهما يخالف قواعد المشروع المعتمدة، و**يفشل عند التشغيل على قاعدة جديدة**:

| الملف | الحجم | المشاكل المثبتة |
|---|---|---|
| `supermarket-inherited.sql` | 23 KB | يكتب `auth.users` (يخالف R-18) · يكتب هوية `company_settings` (يخالف R-02) · يشير إلى `reference.sql` المحذوف |
| `stationery-inherited.sql` | 129 KB | **489 معرّف UUID ثابت** مأخوذة من قاعدة المطوّر · يكتب `auth.users` (يخالف R-18) · يعتمد على `demo/accounts.sql` المحذوف |

### لماذا لا يعملان

**المعرّفات الثابتة.** الملفان يحتويان معرّفات مأخوذة من قاعدة بيانات المطوّر،
مثل:

```sql
INSERT INTO public.products (id, category_id, unit_id, ...)
VALUES ('ac4a1521-8e10-47ee-8da1-8c4aa7dcc645', ...);
```

هذه المعرّفات **لا وجود لها في قاعدة جديدة**، فيفشل الملف برسالة:
```
ERROR: insert or update on table "products" violates foreign key constraint
DETAIL: Key (category_id)=(ac4a1521-...) is not present in table "categories".
```

**الاعتماد على ملف محذوف.** `stationery-inherited.sql` كان يجب أن يُشغَّل بعد
`demo/accounts.sql`، لأنه يحمل `created_by` يشير إلى معرّفات المستخدمين فيه.
وقد حُذف `accounts.sql` لأنه يخالف القاعدة R-18.

**كتابة هوية الشركة.** `supermarket-inherited.sql` يكتب `company_settings` —
اسم الشركة والعملة والرقم الضريبي. ومن يجرّبه يجد شركته تحمل اسم شخص آخر.

## ما البديل؟

`03_samples/sample-mill.sql` هو **النموذج الصحيح**. انظر إليه عند كتابة عيّنة
جديدة:

| ما يفعله الملف الصحيح | ما يفعله الملفان الموروثان |
|---|---|
| `(SELECT id FROM categories WHERE name='Wheat')` | `'ac4a1521-8e10-...'` |
| لا يمسّ `company_settings` | يكتب الهوية |
| لا يمسّ `auth.users` | يُنشئ مستخدمين |
| ملف واحد بأقسام مرقّمة | ملف واحد ضخم بلا تقسيم |
| بيانات نظيفة | «ghfgdfsd» كاسم عميل |

## هل نحتاجهما؟

**لا.** بيانات العرض الخاصة بالبقالة والقرطاسية يمكن إعادة كتابتها على نمط
`sample-mill.sql` عند الحاجة. المحتوى (أسماء المنتجات والأسعار) مفيد مرجعيًا،
لكن البنية غير صالحة للاستخدام.

إن أردت عيّنة بقالة أو قرطاسية:

1. انسخ `../03_samples/sample-mill.sql`.
2. احتفظ بالهيكل والأقسام الستة.
3. استبدل الأسماء والأسعار من الملف الموروث المناسب.
4. حوّل كل معرّف ثابت إلى `(SELECT id FROM ... WHERE name = '...')`.
5. احذف أي كتابة على `auth.users` أو `company_settings`.
6. اختبر: `supabase db reset` ثم شغّل الملف **مرتين**.

وثّق العيّنة الجديدة في جدول الملفات في `../03_samples/README.md`.
